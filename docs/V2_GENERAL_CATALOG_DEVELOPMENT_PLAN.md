> 状态：当前执行基准；政府生鲜 A～H、设备 I～L 已完成；M 因 6 组历史 iMac 重复身份未通过最终验收，待限定修复授权

## 1. 当前目标

项目保留全品类价格采集和存储能力。当前已实现的 V2 来源为**中国大陆政府公开生鲜价格和 Apple、华为、小米、OPPO、vivo 官方设备**；不读取或迁移 V1 业务数据。系统负责采集、规范化、校验、审计和 MySQL 持久化，不负责对话应用、理赔规则、价格推荐或查询 API。

设备改造的现状差距、表映射、必要的小型迁移、运行保护、旧代码退出和分阶段验收，以[V2 设备原生采集改造计划](V2_DEVICE_NATIVE_COLLECTION_PLAN.md)为准。I～L 已完成五品牌原生多 SKU 和标准商品链路、共用管道、变价与缺失保护，以及只读重放/审计、显式设备调度和 V1 运行依赖删除；仅在本地专用环境验证，未访问真实商城或修改公司库。本文第 2～9 节继续记录政府阶段的实现基线，不代表新阶段排除已授权的官方商城。

政府阶段 A～H 的完成标准是：

1. 接入 2 个互补的政府公开来源；
2. 保存来源公布的每一个价格时点，并保留原始证据；
3. 明确区分零售均价与批发均价，不把二者混为“商品售价”；
4. 同一官方数据重采保持幂等，官方修订可以追溯；
5. 在公司专用 device_price schema 中安全运行，不影响其他 schema；
6. 不增加 Redis、消息队列、数据仓库或新的服务进程。

本项目按 demo 交付，不建设新的调度服务、告警平台、运行监控或 7 日连续运行机制。更新默认由操作者按需执行手工命令；原有轻量 scheduler 已改为显式选择设备来源的可选入口，不调度政府来源。数据质量依靠来源白名单、严格解析、中央价格门禁、原始证据和失败不推进当前价来保证。

2026-09-10 已先按旧版五品牌入口恢复 V1 设备 demo 数据，未改变 V2 政府价格；该次操作见[运行手册](OPERATIONS_RUNBOOK.md#23-单独恢复或更新-v1-设备-demo)。随后新增的改造目标是：复用站点抓取逻辑，统一到原生 V2 链路，不做长期的 V1 DTO 转换包装层，也不先清库。V1 旧表默认保留为静态数据，是否删除另行确认。

V1 恢复已完成：103 个产品、1,114 条 SKU 当前价入库，V2 的全部表内容保持不变；验收与已知覆盖限制见[V1 重采记录](V1_RECOLLECTION_20260910_REPORT.md)。

## 2. 数据口径

| 项目 | 当前约定 |
| --- | --- |
| 地区 | 中国大陆；保存来源明确给出的全国、省或市代码 |
| 币种 | CNY |
| 品类 | 生鲜食品；第一批为蔬菜、水果、肉类和蛋类白名单 |
| 来源 | 政府部门官方网站公开页面、公开附件或公开接口 |
| 价格 | 来源明确发布的零售均价或批发均价 |
| 时间 | 优先使用来源数据日期；系统抓取时间单独保存 |
| 原价 | 通常为 NULL；“前一日价格”、环比和指数都不是原价 |
| 费用 | 不包含运费、税费和额外包装费；政府均价使用 NOT_APPLICABLE |
| 历史 | 追加式点时事实；相同来源数据重放不重复写入 |

政府发布价是价格参考证据，不等同于某个商店在售 SKU。后续应用可以选择零售或批发口径，本项目只保证两种性质可区分、可追溯。

## 3. 第一批来源

### 3.1 主来源：商务部商务预报“百家日报”

- 发布方：商务部商务预报；
- 入口：[全国农副产品日报数据](https://cif.mofcom.gov.cn/cif/html/screen/bjScreen.html)；
- 当前形态：按品种展示地区、市场、当日价格、前一日价格和环比；
- 数据性质：各批发市场当日批发价；
- 地区：使用页面明确给出的省级地区，市场名称单独保留；
- 用途：以 15 个高频生鲜品种形成跨地区、同日可比的主体数据。

### 3.2 补充来源：上海市主要主副食品价格信息

- 发布方：上海市发展和改革委员会；
- 入口：[价格监管动态](https://fgw.sh.gov.cn/fgw_jgjgdt/)；
- 当前形态：工作日高频发布文章，并提供 .xls 附件；
- 数据性质：上海市主要品种平均零售价；
- 地区：CITY/310100；
- 用途：用 8 个主副食品补充城市零售均价口径，不与批发价合并。

页面当前发布频率是实施时的观测结果，不视为政府提供的服务等级承诺。连接器必须允许来源暂停、节假日停更和页面结构调整。

### 3.3 首批品种

商务部主来源支持 15 个精确白名单品种：大白菜、黄瓜、胡萝卜、白萝卜、西红柿、土豆、洋葱、蒜头、生姜、茄子、西兰花、鲜鸡蛋、后臀尖、牛腿肉和白条鸡。上海补充来源支持青菜、鸡毛菜、大白菜、黄瓜、胡萝卜、红富士苹果、鸡蛋和精瘦肉。

来源名称、规格或单位不能明确映射时进入待复核，不使用模糊匹配补齐。商务部导航中的“鲜猪肉”和“鲜牛肉”页面实际标题分别为白条猪和整牛，不满足同名同口径条件，因此不进入当前白名单。

首批通过后只扩展配置白名单和规则 fixture，不为每种蔬菜新建表或连接器。

## 4. 本阶段不做

- 不接入京东、淘宝、拼多多、盒马、叮咚买菜等商业平台；
- 不采集个人站、社交媒体、搜索缓存或聚合站；
- 不解析 PDF、图片或 OCR，第一版只处理 HTML 和 .xls；
- 不采集促销、会员、优惠券、配送费或门店库存；
- 不把周报中的涨跌百分比、价格指数或区间推导成商品价格；
- 不追求全国所有政府网站或全部生鲜品种覆盖；
- 不实现自动价格推荐、理赔计算、对话查询或统计报表；
- 不把 `v2_` 表改名，不为并存的 V1 表增加额外删表迁移。

## 5. 数据库使用方式

继续使用已实现的 13 张 v2_ 业务表，不新增业务表。

政府数据映射如下：

| 领域字段 | 映射规则 |
| --- | --- |
| source_channel.source_type | PUBLIC_DATA |
| merchant | 政府发布汇总使用合成公共来源；有明确市场时使用市场名称 |
| source_listing | 来源 + 市场层级 + 品种 + 规格 + 单位形成稳定键 |
| listing_revision | 保存来源名称、规格、单位和规范化品种；这些字段变化时产生新版本 |
| price_nature | 零售均价用 RETAIL_AVERAGE，批发均价用 WHOLESALE_AVERAGE |
| price_type | PUBLISHED_VALUE |
| pricing_basis | UNIT_QUOTED |
| original_price | NULL；original_price_type=NONE |
| region | 只使用来源明确表达的行政范围，不从市场名称猜测市区 |
| price_observation.observed_at | 来源数据日期或明确的观测时间 |
| crawl_record.fetched_at | 系统实际下载时间 |
| price_current | 每个来源商品、地区的最新可信发布值指针 |

只做四项小型兼容调整，不改变表数量：

1. PriceNature 增加 RETAIL_AVERAGE、WHOLESALE_AVERAGE；旧的 MARKET_AVERAGE 仅保留兼容，不用于新政府连接器；
2. 价格候选 DTO 增加可选 source_observed_at，没有来源时间时才退回抓取时间；
3. 批量数据集的价格候选增加可选 evidence_hash，用来源行的业务证据生成，避免文件中无关行变化制造伪修订；完整文件哈希仍保存在 crawl_record；
4. 来源日期只有“日”精度时，按 Asia/Shanghai 当日 00:00:00 转为 UTC，并在来源属性中保存 time_precision=DAY，不伪装成精确时刻。

同一日期、同一来源行、同一行级证据哈希的重采保持幂等。若政府在同一数据日期替换附件并修改数值，只为变化行新增修正观察并通过 supersedes_observation_id 指向旧观察，禁止覆盖历史；文件中其他行及页面外壳变化不制造价格修订。

## 6. 最小技术方案

沿用现有 Python、HTTP 抓取器、SQLAlchemy、Alembic 和 MySQL：

    手工 CLI
      → 政府来源连接器
      → HTTP 下载 HTML/XLS
      → 批量行解析
      → 生鲜名称/单位规则
      → 中央价格质量门禁
      → 13 张 v2_ 表

具体选择：

- HTML 继续使用现有解析能力；
- 只新增轻量 xlrd 读取旧版 .xls，不引入 pandas；
- 不使用 Playwright，除非政府公开页面确认只能通过浏览器取得；
- 商务部旧站只在该连接器内使用仍校验证书的 TLS 1.2 兼容上下文，不降低其他来源的 TLS 策略；
- 增加一个窄范围的“数据集连接器”接口：一次下载一个政府文件，解析为多条来源商品，避免每行重复下载；
- 数据集中的每一行仍复用现有品类规则、价格门禁和 Repository，不另建 ETL 框架；
- 原文件通过现有证据存储保存哈希和路径，MySQL 不存整份文件正文。

## 8. 手工更新与时效

demo 默认策略保持简单：

- 操作者按需运行 `catalog crawl`，可以每天运行，也可以验收时单次运行；
- 相同官方数据反复获取不新增价格事实；
- 命令输出来源日期、解析数量和退出码，操作者据此判断是否停更或结构变化；
- 来源停更不会删除上一条可信价格；
- 不接入节假日日历、定时补采、告警平台或新的监控表。

“最新价格”定义为该来源、品种、地区最新的**来源数据日期**，不是最后一次下载时间。系统不能保证政府网站何时发布，只能保证发现新数据后按计划采入并显式暴露陈旧状态。

## 9. 质量与安全门禁

以下任一情况只留失败证据，不推进 price_current：

- 发布日期、表内日期和附件日期互相冲突；
- 品种、地区、市场、单位或金额缺失；
- 金额不是正数，或单位不能准确换算；
- 页面只有涨跌幅、指数、范围或文字描述，没有明确人民币值；
- 来源内容结构指纹变化且解析器未明确支持；
- 重定向离开批准的政府域名；
- 需要登录、验证码、个人 Cookie 或未公开签名接口。

真实运行保持低频、只读，遵守站点公开规则。仓库不保存 Cookie、Token、完整未脱敏网页或公司凭据。
