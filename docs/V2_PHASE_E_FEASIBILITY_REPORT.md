# V2 阶段 E 首轮报告：大型电商可行性门禁

> 报告状态：历史决策报告；E0 首轮门禁已完成，当前大型电商路线已结束
> 实测窗口：2026-08-21，中国大陆网络环境
> 生产影响：无；未连接数据库、未写入业务数据、未保存真实页面、未登录或绕过访问控制

> 2026-08-21 决策：当前生鲜数据源改为政府官方网站公开数据。本报告不再表示“等待 API 后继续”的活动待办，后续执行基准见 [V2 生鲜政府价格数据开发与实施计划](V2_GENERAL_CATALOG_DEVELOPMENT_PLAN.md)。

## 1. 结论

京东、天猫和拼多多是全品类扩展最优先评估的三类大型综合电商，但首轮验证均未满足正式 HTML 连接器的最低条件：匿名访问、明确地区、稳定卖家、确定 SKU 和无条件直接价必须能在同一份来源证据中绑定。

- 京东公开商品地址在匿名浏览器中最终进入登录页；
- 天猫当前 `robots.txt` 禁止通配匹配的带查询参数路径，而商品详情通常依赖 `item.htm?id=...`，因此没有继续请求详情页；
- 拼多多公开商品地址在匿名浏览器中最终进入登录页；
- 三个平台都没有取得可支持本项目用途的外部数据授权或开放平台凭据。

因此本轮结论不是“解析器尚未写好”，而是数据入口尚未通过合规和可访问性门禁。当前不得新增真实平台连接器、启用来源种子、启动连续采集或把搜索引擎缓存当作价格来源。项目已选择政府公开数据作为当前生鲜路线，不再等待商业平台开放能力。

## 2. 验证边界

本轮只执行以下操作：

- 使用匿名 `DevicePriceTestBot/1.0` 检查三个官方 `robots.txt`；
- 对规则未明确禁止的两个公开商品地址各执行一次只读 HTTP/浏览器 smoke；
- 不传账号、Cookie、Token、精确地址或公司信息；
- 不点击登录、不处理验证码、不构造签名、不调用页面内部接口；
- 不重试访问控制、不并发扫描商品、不做搜索或列表遍历；
- 只记录状态码、跳转类型和字段可得性，不提交完整页面或响应体。

平台用户协议和 `robots.txt` 只能提供风险边界，不能替代平台授权或公司法务意见。项目负责人对低频测试的授权仅覆盖本轮测试行为，不等于获得平台对持续商业采集的许可。

`HEAD 200` 不能视为商品可采集。两个平台的脚本渲染结果都进入登录页，说明状态码只证明入口返回了 HTML，不能证明匿名环境能取得商品事实。项目不得通过复用个人登录态、模拟登录、读取 Cookie 或调用签名接口来改变这一结论。

公开搜索索引曾能显示部分标题、店铺名和旧页面文案，但仍缺少可绑定的地区和实时价格，而且它属于第三方缓存。它既不满足“直接来源证据”，也无法证明采集时点、规格和当前可售状态，因此不能进入 `v2_price_observation`。

## 5. 官方开放能力评估

### 5.1 京东

[京东开放平台](https://jos.jd.com/)公开了注册开发者、创建应用、权限申请、授权和 API 调用流程。它是后续优先 POC 入口，但必须先确认可申请的商品能力是否返回：

- 指定配送地区下的可售状态；
- 平台自营、品牌官方或第三方卖家身份；
- 完整 SKU 规格；
- 不含券、会员、补贴、运费和包装费的商品直接价；
- 明确原价类型，而不是市场参考价或起售价。

仅能得到推广价、结算价、广告素材价或授权商家自有商品时，仍不足以支撑全平台理赔参考价。

### 5.2 天猫/淘宝平台

[淘宝开放平台商品 API](https://developer.alibaba.com/docs/api.htm?apiId=20)要求应用参数、签名，并把单商品详情标为需要授权；[商品 API 目录](https://developer.alibaba.com/docs/api.htm?apiId=10)也表明所谓产品搜索能力并不是面向消费者的全平台商品搜索入口。后续不能假设“有开放平台”就等于可以取得任意店铺、任意地区的实时成交前价格。

如能获得正式应用权限，应优先做 API POC；在此之前不继续访问受 robots 限制的详情路径。

### 5.3 拼多多

本轮无法从[拼多多用户服务协议](https://www.yangkeduo.com/pdd_user_services_agreement.pdf)确认本项目对商品数据持续采集的权限。后续应通过平台正式合作入口确认商品详情、SKU、地区和价格权限。即使推广类接口可以返回价格，也必须证明该值是用户无需领券、拼团、会员或补贴即可直接购买的商品价，否则只能作为拒绝观察或不接入。

## 6. 正式连接器准入标准

一个平台只有同时满足以下条件，才能从 `NO-GO/PENDING` 进入连接器开发：

1. 平台授权或公司合规意见明确允许目标数据、访问方式和频率；
2. 精确目标路径不被当前 robots 规则禁止；
3. 匿名或正式 API 凭据能稳定访问，不依赖个人账号和人工验证码；
4. 每条事实能绑定地区、卖家、商品、可销售 SKU、采集时点和人民币价格；
5. 能区分直接价与会员、券、补贴、拼团、定金、分期、预估和推广价格；
6. 能排除运费、税费和包装费，无法拆分时明确拒绝；
7. 原价只有在来源明确标注类型时保存，否则为 `NULL`；
8. 原始证据可脱敏、哈希和按批准期限保存，不含 Cookie、Token、签名或个人数据。

通过一次 smoke 后，还需完成最小连续试验：

- 至少 3 个代表性 SKU；
- 至少 2 个明确地区；
- 至少 6 轮采集并跨越 3 个自然日；
- 每轮记录 HTTP/业务状态、字段覆盖、解析结果和结构指纹；
- 访问控制事件为 0，价格语义未决项为 0；
- 结构变化不得静默写入，任何漂移先使批次失败并人工复核。

以上数字是可行性门槛，不是生产频率。正式调度频率仍需根据平台授权、价格时效和运行监控单独确定。

## 7. 本阶段已明确不做

- 不创建 `JD_CN_WEB`、`TMALL_CN_WEB` 或 `PDD_CN_WEB` 的启用来源记录；
- 不编写针对登录页、风控页或内部签名接口的适配器；
- 不复用浏览器个人登录态；
- 不把第三方搜索引擎、电商聚合站或非授权 API 当作平台原始证据；
- 不连接公司 MySQL，不迁移或清理 V1/V2 表；
- 不保存本轮真实响应体到仓库。

## 8. 最终决策

阶段 E 已结束。京东、天猫和拼多多不进入当前生鲜数据源清单，也不再作为阶段 F～H 的阻塞项。若未来重新提出商业平台需求，应作为独立范围重新确认 API 权限、价格语义、地区和合规条件，不能直接恢复本轮 HTML 方案。
