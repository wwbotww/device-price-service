# V2 阶段 A 构建报告：数据库基础与点时事务

> 完成日期：2026-08-21
> 状态：本地开发与双版本专用数据库验收通过
> 生产影响：无；未连接或修改公司 MySQL 及其他 schema

## 1. 本阶段结论

阶段 A 已完成。项目在保留 V1 10 张业务表和原采集链路的前提下，实现了 13 张 `v2_` 全品类影子表、点时价格领域契约、来源身份与规格版本事务、最新可信价格指针，以及 MySQL 5.7 兼容约束。

当前可以在统一数据库模型中保存任意授权来源、卖家、地区和品类的价格事实，但尚未接入新的真实电商平台，也没有把 V1 数据回填或双写到 V2。

## 2. 已交付内容

### 2.1 数据库结构

新增以下 13 张影子表：

- 标准商品：`v2_brand`、`v2_category`、`v2_catalog_item`、`v2_item_variant`；
- 来源身份：`v2_source_channel`、`v2_merchant`、`v2_source_listing`、`v2_listing_revision`、`v2_listing_match`；
- 价格事实：`v2_price_observation`、`v2_price_current`；
- 采集审计：`v2_crawl_run`、`v2_crawl_record`。

迁移版本：

- `0aafbcfc19d5`：只新增 V2 影子表、索引、外键和 `CHECK`；
- `96524222b3ec`：在 MySQL 5.7 上为 13 张 V2 表建立 `BEFORE INSERT/UPDATE` 校验触发器。

MySQL 5.7 中新增 26 个 V2 校验触发器；加上原有 V1 的 14 个，共 40 个。MySQL 8.0.16 及以上使用原生 `CHECK`，不创建这些兼容触发器。

循环外键按“先建 `v2_source_listing` 和 `v2_listing_revision`，再添加当前版本外键”的顺序迁移；降级先移除该外键，再按依赖逆序删除影子表。迁移测试确认升级和降级均不改 V1 表结构或已有行。

### 2.2 领域与事务

`CatalogPriceObservation` 已实现：

- UTC naive、毫秒精度和 CNY 规范化；
- SHA-256、金额、原价、单位价和地区语义校验；
- 零售/批发直接售价与公开市场人民币均价的独立门禁；
- 会员、优惠券、补贴、定金、分期、起售价、估算价和不可拆费用不能标记为可信当前价；
- 稳定的观察幂等键，同价不同采集时间仍生成不同点时事实；
- 修正观察保留旧事实，并通过 `supersedes_observation_id` 建立审计关系。

Repository 已实现：

- 品牌、品类、标准商品、标准规格、来源、卖家和来源商品的幂等取得或创建；
- 来源商品不可变规格版本，以及已接受当前版本的受控切换；
- 来源版本与标准规格的候选/接受匹配；
- 点时价格追加、当前投影推进和当前投影重建；
- 来源、卖家、版本、批次、证据、地区和价格性质的跨表一致性校验。

当前投影只保存观察指针，不复制价格金额。乱序观察会保留但不覆盖当前指针；拒绝或待复核观察不会推进；同一时间只有显式指向当前观察的可信修正可以替换；来源链接从 5kg 切换为 10kg 等身份变化时，旧版本当前投影会先失效。

## 4. 实施中确认的设计修正

“公开价格指数”可能没有人民币金额含义，不能进入金额事实表。实现将可接受的公共数据限定为 `MARKET_AVERAGE + PUBLISHED_VALUE`，即来源明确发布、单位为人民币的市场平均价；无人民币价格含义的指数只可留在未来的独立公共指标模型，本阶段不建该模型。
