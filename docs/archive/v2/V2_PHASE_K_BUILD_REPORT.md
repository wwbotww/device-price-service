## 2. 运行保护及数据正确性

- 变价超过配置阈值（默认 30%）时，对同来源 listing、规格版本、地区最近的**有金额可信事实**进行比较；无金额状态不能抹掉价差基线。立即复抓整个产品，仅两次完整配置、金额和状态一致且第二次时点更新才写入可信价。第一次证据保留为待确认记录，第二次记录关联两份证据；不一致进入待复核，失败不覆盖旧价。REPLAY 不触发联网复抓。
- 默认产品发现数量下限为既有可信在用产品数的 50%，按产品而非 SKU 计数。不通过时整批失败、不抓详情、不写价、不累计缺失；空发现及发现错误继续明确失败。
- 只有完整默认品类、无商品筛选、非查询重采，且发现与已发现产品采集全部成功、全部非 REPLAY 新时点时，才累计缺失。达到默认 3 次后访问详情；确认失败可使最终批次 PARTIAL，但不会编造下架事实。
- 缺失确认从最近可信观察的不可变记录恢复发现 URL/元数据，不使用初次规格记录的旧地址，也不根据当前 listing 字段重新拼请求。403、登录跳转、超时、无 HTTP 响应、单 SKU/子接口 404 均不能证明整产品下架。
- 合法整产品 404/410 对已有可信规格写 `AVAILABILITY_ONLY/OFF_SHELF`，所有金额和单位价为空，更新来源生命周期；全局标准型号不跟随停用。金额留在自己的历史时点，不伪装成下架时点报价。后续可信重采可恢复在售。
- 已发现产品漏掉既有 SKU 时，记录 `SKU_COVERAGE_INCOMPLETE`、批次 PARTIAL；其余可信 SKU 可提交，遗漏 SKU 不更新、不清空、不推断下架。
- 旧点时、重复证据、条件价、失败解析不恢复当前 URL/生命周期或清零缺失。比较统一使用 UTC 毫秒，与 MySQL 事实精度一致；既有同时点冲突、乱序、版本切换及重建保护继续生效。
- 渠道/地区命名锁内恢复同渠道、地区、品类范围过期的设备 RUNNING；其他范围及政府 commodity 不受影响。取消得到 CANCELLED 终态。未增加调度或监控系统。

实现集中在 [设备保护](../../../src/device_price_service/services/catalog_device_guards.py) 与 [共用流水线](../../../src/device_price_service/services/catalog_crawl_pipeline.py)，不引入品牌专属持久化分支。

## 3. 入口与数据库边界

- `catalog sources` 列出五品牌设备和两个政府来源；五品牌均可使用 `catalog smoke/crawl --channel`。smoke 不连接 MySQL，正式采集保留来源启用和真实开关双门禁。
- 旧 `adapters/crawl/smoke/replay/scheduler` 命令只返回退役提示，已删除旧 CLI 执行函数，不构建旧采集运行时。完整 V2 replay、审计和显式可选调度仍在阶段 L。
- 历史 `db seed/check/audit` 与通用 V1 服务尚待 L 清理；`db seed` 仍会写 V1 参考表，不能声称仓库所有 V1 写入口都已删除。V2 初始化应使用 `db seed-devices`。
- 沿用既有四项运行保护配置，`.env.example` 无需新增变量。不新增业务表或迁移；代码 head 仍为 `b72c910e4f31`。
- 本轮仅使用本地专用 `device_price_test`，没有连接公司库、访问真实来源、迁移 V1 数据、提交或推送 Git。公司最近确认的 head 仍为 `96524222b3ec`。

具体命令及错误处理见[运行手册](../../OPERATIONS_RUNBOOK.md#2-手工采集)。
