## 2. 重放与审计如何保持可信

- 新记录使用不可变发现上下文及原始抓取时间，完整重放共享证据内全部 SKU/政府行；不从当前 listing 的名称、URL 或规格反推历史。
- 对实际已部署的商务部、上海旧证据，使用保存的来源页面、日期和品种白名单确定恢复上下文，不增加格式注册系统；恢复不了就明确失败，不补抓或修复原记录。
- 重放输出 `STATIC_REPLAY`、逐行当前静态校验和单独的 `historical_validation`。未确认的价格突变仍为 `PARTIAL`，不能因重放解析通过就被当成新可信报价。已确认 404/410 仅核对原无价状态事实，不解析错误页，不携带旧金额。
- 原始证据须通过路径范围、哈希与记录大小检查；错误清单、缺文件、损坏或截断 gzip 都明确失败。只读访问不会创建证据目录。
- 审计覆盖当前指针、最新可信规格/观察、政府修订、设备同点冲突、标准身份与匹配、证据归属、价格/无价状态门禁和批次终态。变价复抓的第一条 PENDING 证据可合法保留，不使最终成功批次误报。
- 缺少必需表或数据不一致计入 `critical`；过期批次/价格、启用但未采集的来源和未确认变化仅计入 `warnings`，禁用且未运行的来源不误报。审计不自动终结批次、重建指针或修改数据。

`catalog replay` 全部静态通过退出 0，失败或部分通过退出 1；命令参数错误退出 2。审计存在 critical 才退出 1，warning 不影响退出码。操作与错误处理见[运行手册](OPERATIONS_RUNBOOK.md#26-原始证据只读重放)。

## 3. V1 退出与数据库边界

删除被替代的 V1 流水线、持久化服务、ORM/Repository/种子、专用 DTO/校验、品牌注册表和旧运行时。旧顶层 `adapters/crawl/smoke/replay` 与 `db seed` 命令及对应 Makefile 目标删除，没有保留报错包装或两套实现。共享时间、列定义和 Repository 异常移到独立小模块。

运行时元数据只注册 13 张 V2 表。历史 Alembic 链保持不变，完整升级仍创建 10 张 V1 和 13 张 V2 业务表，MySQL 5.7 保留 40 个约束触发器。自动生成迁移仅反射 `v2_` 表，保护旧表及其他非 V2 表。本阶段没有新增迁移、删表或改名，代码 head 仍是 `b72c910e4f31`。

仅含 13 表的测试证明应用不依赖 V1；实际 Alembic 测试证明旧表共存和 5.7 触发器兼容。正式部署仍须运行 Alembic，不能用 `metadata.create_all` 替代 5.7 约束安装。已删除的 V1 单测/集成用例由 V2 行为用例替代；历史表只在迁移和隔离测试中反射，不恢复业务 ORM。

可选 scheduler 沿用现有间隔、单任务不重叠与来源/地区命名锁；启动前验证全部所选设备，每次执行再校验来源开关，批次标记 `SCHEDULED`。默认不启动，不新增调度表、服务或监控。
